# Codex 成员群聊

HarvisBar 的「成员群聊」使用 Codex 原生 App Server 执行，每个成员拥有独立的原生会话。同一账号的成员共用连接，不共用 thread。

## 使用

1. 从菜单栏 Codex 面板打开「成员群聊」，或使用 Codex 菜单中的同名入口（⌘⇧G）。
2. 创建群聊并选择已有项目目录。
3. 添加成员，填写唯一名字、职责和已登录的 Codex 账号。
4. 在成员菜单中设定群主，收件人随即切到「群主协调」。向群主描述目标后，群主在自己的原生会话里分解任务、指派成员、汇总结果并复核；只有经过原生历史核验的结构化计划会触发后续执行。
5. 在权限菜单中一次设置全体成员「只读讨论」或「项目写入」。项目写入只授权所选共享项目，仍保留原生审批，未授权全机访问。

没有群主的新群默认直接发送给全体成员。直接发送时，正文写出成员名字即可定向指派，例如「架构师设计方案，审查员检查结果」只唤醒这两位，无需输入 `@`；原来的 `@成员名` 仍兼容。也可从收件人菜单选择成员；选择「仅记录，不唤醒」时，消息只记入共享时间线，即使正文出现名字也不会执行。

打开群聊后可直接输入。发送前，输入框附近会显示实际接收成员。名字按原文精确识别；同一位置匹配多个名字时采用最长名字，英文和数字名字按词边界匹配。

发送后保留当前接收方式；选择「仅记录」或指定成员后，后续消息继续使用该选择，直到主动更改。正文中的名字仍按上述规则参与实际接收成员的判断。

翻阅旧消息时，新回复不会将页面拉回底部；时间线会提示新增消息数量，点击「返回最新」即可继续查看。停留在底部时，新回复自动跟随；主动发送消息也会显示到最新位置。

默认讨论权限是只读。明确开启项目写入后，成员才可修改所选项目。共享群记录会按成员的已读位置送入上下文；本条完整请求会单独作为当前任务传入，不受历史截取或已读位置影响。成员职责作为工作背景，历史请求与回复作为参考。其他账号的私聊不会自动进入群。

同一项目一次只允许一个写入回合，此限制也适用于绑定相同目录的其他群，并包括持有写入权限的群主回合。全员写入请求会保存并依次执行，不再因收件人多于一位而拒绝。其他成员仍可只读审查。需要并行修改时，先准备独立 Git worktree，并分别选择对应项目目录；程序不会自动创建或合并工作树。

成员菜单提供编辑名字与职责、原生历史、停止、分叉和账号交接。改名后，正文使用新名字指派；新职责从下一条指令生效，原生会话和历史归属保持不变。

草稿按群聊自动保存，包含正文与接收成员，也会保留「群主协调」和「仅记录」模式。关窗或正常退出后，重新打开会恢复上次群聊和未发送内容，不会自动发送。群主、项目权限和后台接入开关属于群设置，重启后保留。旧版群首次加载时没有群主，群级权限默认只读，需要明确设置。保存失败时显示错误并保留内存中的输入；若此时退出，会提示取消退出或继续退出。

关闭群聊窗口不会取消后台任务。程序重启后先恢复账本并核对原生状态，无法证明是否执行过的投递标为「待核实」，不会自动重发。

群主每轮决策更新共享摘要、关键决定和待办，可从「协作」菜单查看。成员结果会回送到同一群主原生 thread；重启使用该 thread 恢复，线程是否出现在 Codex 桌面列表不影响群聊引用。协作任务、依赖、已处理的原生回合及请求回执在本地持久保存。每次协作默认最多 8 轮群主决策、24 个成员任务，到达预算后显示待继续，不会假报完成。

开启「后台接入」后，本机其他智能体可通过 MCP 或经过鉴权的本地 HTTP 接口列出群、提交任务、读取进度和结果、停止或核对状态。发送立即返回持久回执，调用方使用稳定的 `requestID` 重试以避免重复执行。关闭接入开关仅关闭外部访问；窗口关闭后已接受的任务继续运行，退出 HarvisBar 后执行引擎与接口不可用。配置和示例见 [群聊控制接口](group-control-api.md)。

## 会话语义

| 操作 | 实际行为 |
| --- | --- |
| 继续聊天 | 使用原账号、原项目、原生 thread 恢复上下文。 |
| 原生分叉 | 在原账号中创建新的分支，保留来源 thread，原会话不继续写入。 |
| 换账号交接 | 保留群成员身份，目标账号创建独立 thread；下一次被唤醒时接收共享群记录，私有原生历史不迁移。 |
| 改变读写权限 | 空闲时在同一原生 thread 恢复并调整权限，保留原生上下文；明确从未执行且已不存在的空绑定可重建并记录来源。 |

群内支持命令、文件、权限审批和 Codex 的结构化问答。审批绑定原连接代次，过期请求不能复用授权。MCP elicitation 当前可在群内取消，尚不提供通用 MCP 表单编辑器。

账号身份通过原生 `account/read` 核对；环境隔离不会继承宿主的 OpenAI/Anthropic API key。账号或配置发生变化时，旧连接失效，后续任务需要重新核对。模型与推理档位从账号实际模型目录选择并固定在绑定上。

## 本地数据与验收

群聊账本、队列和独立的 `composer-v1.json` 草稿文件位于 `~/Library/Application Support/HarvisBar/GroupChat`，目录权限为 0700，文件权限为 0600。该目录保存群内分享的内容、未发送草稿和原生会话引用，不复制账号凭据。

自动化验证包括原生 RPC、账号隔离、绑定校验、权限变化、交付不确定性、停止、历史恢复和消息去重。真实账号验收是显式 opt-in，使用独立测试项目、测试账本和新建原生会话。

`HarvisGroupLiveAcceptanceTests` 验证三账号、同账号双成员、共享文件读写与审查、重启恢复、原生分叉、账号交接及账号故障隔离。真实验收需要显式提供 `HARVIS_GROUP_LIVE_ACCEPTANCE=1`、`HARVIS_GROUP_LIVE_HOMES`、`HARVIS_GROUP_LIVE_OUTPUT` 和 `HARVIS_GROUP_LIVE_PROJECT`。

滚动回归使用正常 NSApplication 事件循环：100 条聊天、25 条运行中、每 2 秒更新。仅 Codex 面板的聊天行使用惰性布局，面板中的运行点静态显示；其他窗口保留原来的运行状态动画。测试驱动等待 App 自己完成 20 秒采样，不以离屏布局时间代替滚动延迟。

本次验收使用 bundled Codex CLI `0.163.0-alpha.11`；协议升级后应重新核对模型目录、原生恢复和审批契约。源码、测试记录、构建摘要及 App bundle receipt 共同确定版本，不以显示版本号作为唯一依据。
