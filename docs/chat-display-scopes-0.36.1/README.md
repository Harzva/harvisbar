# 0.36.2：基于 0.36.1 的显示范围与流畅度优化

## 基线与范围

本功能从已安装 0.36.1 构建凭据的源码提交 `7d5f9ee` 建立独立工作分支。
不依赖其他工作副本尚未发布的 Agent Managed 重构。

验收目标：DSH 不出现输入框；不同 Codex 账号与不同智能体的卡片可以混合展示；
可选择全部、单一智能体、单一账号或多选组合；记住当前范围并能保存、恢复默认范围；
Codex 账号管理与 DSH 管理是独立入口；继续按规范化项目路径合并卡片。

## 实现与边界

- `ManagedChatDisplayScope` 管理显示范围。智能体集合与 Codex 账号集合分别筛选，
  Codex 账号限制不影响 DSH / WorkBuddy。账号集合为 `nil` 表示全部，为空表示不选任何账号。
- `ManagedChatDisplayScopeMenu` 提供组合选择和单一来源快捷选择。当前范围和默认范围
  使用各自的版本化 UserDefaults key；未配置时默认全部来源。移除账号后保留用户选择，
  不把失效的显式选择自动扩大为全部账号。
- 复用 0.36.1 已有的按 Home 缓存和后台预热。统一列表从所有可见 Home 投影，
  后台定时刷新覆盖所有可见账号；原生单账号弹窗仍保持原有管理账号语义。
- 卡片身份继续使用 provider / sourceScope / sourceID。卡片上的账号标签、打开、
  新窗口、交接目标打开、工作台、输入读取和派发使用来源 Home，并验证来源账号可见且仍包含该会话。
  不以当前管理账号替代无法解析的来源。项目治理依然接收完整目录，显示过滤不修改项目数据。
- 项目归组继续调用现有 `ManagedChatProjectResolver`，过滤后同一路径仍为一组。
  详情面板也遵守当前过滤结果，不显示已被排除的选中卡片或项目。
- 管理模块包含原有 Codex 添加、选择管理账号、备注、移出和恢复功能，以及已有的
  DSH Runtime Catalog 入口。DSH 生命周期管理能力复用 0.36.1 的实现。
- DSH 不创建 composer；只读占位改为无边框文字。保留矩阵卡片高度与底部操作行对齐。

## 流畅度优化

- 路径检查使用带锁、最多 1024 项、5 秒有效期的缓存；自定义 FileManager 继续走原始解析，
  手动刷新清空路径缓存。缓存不会永久保留已经变化的路径或 symlink。
- 项目候选计算先按项目分组会话，不再对每个项目重复扫描全部会话和读取文件系统。
- 所有卡片共享一次分析候选目录。会话、账号可见性、项目归属、任务计划和计划新鲜度变化
  立即使缓存失效，另有 5 秒有效期。单卡输入、分析结果与权限判断仍实时计算，不缓存发送权限。
- 200 张合成卡片 / 20 个项目的 Debug 单轮状态计算：优化前 9535 ms，优化后 91 ms；
  同时进行 Release 编译的全量回归中为 400 ms。这是计算基准，不是滚动帧率或不卡顿保证。
- 0.36.2 全量 Swift 测试：524 项通过。首次路径访问仍可能同步读取文件系统，
  如网络盘本身阻塞，仍需要后续采样定位；本次没有宣称消除所有环境导致的停顿。
