### 2.1 DSH/xxsuite 复用门禁

用户于 2026-08-30 要求禁止重复实现 DSH/xxsuite 已有能力。实施前的代码级审计锁定以下决策：

- HarvisBar 内部进程执行只能复用 `HarvisVersionProcessRunner`；旧 `BoundedProcessRunner` 只是兼容 facade，不得出现第三套 spawn/supervisor。
- DeepSeek Harness `subprocess`/`subprocess-local` 与 DSH Mobile Developer 的 supervisor/latest-wins 实现作为 MIT 合同和测试 oracle；Node/Cordis 运行时不直接嵌入 Swift 进程。
- DSH Market 的 source/version/repository-evidence 字段语义可移植为纯 DTO/解析规则；任何 fetch/update/worktree/merge 写操作不得进入本次只读页面。
- Session Board Supervisor 的状态/无障碍语义只作交互参考；不复制无可验许可证的构建产物、JS/CSS 或 SVG。
- Phase 3 的闭环点击必须复用现有 DSH UI Test + Computer Use 基础设施与 fresh-observation/rootRef 规则，不新造一套自动化驱动。

复用不等于跨语言复制源码：同运行时且许可证清晰的组件可直接依赖；跨 Node/React/Swift 边界时只复用 DTO、状态机、AX 契约和测试 oracle。

所有Phase的Ownership都受同一窄例外约束：阶段实施与测试完成后，收尾command恒可且只可同步本文件中该Phase的checkbox/status/脱敏evidence，并原子覆盖`docs/harvis-version-management/NEXT_GOAL.md`到拓扑中的下一Phase；Phase 4则写唯一最终关闭记录。该bookkeeping例外不得修改其他Phase的产品Ownership、增加运行时allowlist、夹带源码改动或进入下一Phase实现；runtime仍绝不读取这些untracked docs扩张stage范围。
