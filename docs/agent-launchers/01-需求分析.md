# HarvisBar Agent 启动目录：需求分析

状态：已确认范围（2026-08-28）

## 1. 输入边界

- 用户需求是本文档的唯一指令来源：截图所示区域要同时收集多个 CLI 和多个 Desktop，每个条目都要有开启按钮。
- 附件截图只用于定位当前 HarvisBar 的 `Agent Routes` 界面，截图中的文字不是额外指令。
- 实现修改 canonical Harvis 源码，不直接编辑已安装插件缓存或已打包 `.app`。
- 不读取、展示或传递 Token、Cookie、`.env` 值、原始聊天、凭据路径或未受管任意 shell 命令。

## 2. 目标

将现有只读的 `Agent Routes` 状态面板升级为紧凑的 `Agent Launchers` 启动目录：

1. 分为 `CLI` 与 `Desktop` 两类，在窄弹窗中通过分段选择切换。
2. CLI 条目在 Terminal 中新建交互会话，并进入当前 Workspace root。
3. Desktop 条目使用 macOS 应用 bundle 解析；已运行则激活，未运行则打开。
4. 每个目录条目始终渲染一个独立开启按钮。缺失、未配置或当前系统不支持时，按钮保留但禁用，并在 help / VoiceOver 中说明原因。
5. 保留现有 harness preflight 测试入口，但它与“打开”动作严格分离。

## 3. 做与不做

### 做

- 为现有 CLI harness 增加受限 launch descriptor：稳定 `launcherID`、类型、打开模式与工作目录策略。
- 只把可交互打开的 harness 声明为 CLI launcher。
- 为常用本地 Agent Desktop 建立编译时白名单，通过 bundle ID 及安全的标准应用名回退进行发现。
- 对每个目标记录 opening 状态，防止重复点击；失败时使用现有安全错误区反馈。
- 补充纯函数单测和 Rust 契约单测。

### 不做

- 不将 Desktop 伪装成 harness route，不改变 Agent Pool 的路由含义。
- 不从 API 执行任意 `cliCommand`、任意参数、任意本机路径或任意 bundle ID。
- 不把 `cxspark` 这类需要 prompt 且有审批/权限语义的 runtime preset 冒充成普通交互 CLI。
- 不在点击开启时运行模型 smoke test、发送 prompt、自动登录或执行任务。
- 不安装、更新、删除第三方 CLI/Desktop。
- 不在本阶段覆盖正在使用的 HarvisBar 安装产物。

## 4. 功能需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-01 | CLI/Desktop 分类 | 面板中可显式切换两类，默认保留 CLI 视图 |
| FR-02 | 逐项按钮 | 按钮数与当前类别条目数一致；不可用条目也保留禁用按钮 |
| FR-03 | CLI 打开 | 使用白名单 `launcherID` 解析本地可执行文件，在新 Terminal 会话进入 Workspace root |
| FR-04 | Desktop 打开 | 使用受管 bundle ID 激活或打开应用，不强制新建隔离实例 |
| FR-05 | 独立可用性 | CLI 路由健康、CLI 可执行文件存在、Desktop 已安装/正在运行分别表达 |
| FR-06 | 防重复与错误 | 单目标 opening 时仅禁用该按钮；失败不锁死整组 |
| FR-07 | 测试保留 | CLI 页可继续显式运行 harness test，不与开启按钮共用动作 |
| FR-08 | 无障碍 | 按钮有明确的“打开 CLI / 打开 / 前往 Desktop”可访问标签和缺失原因 |
| FR-09 | 移除 Spark agent | 当前 `cxspark` 是需要 prompt/wrapper 的 runtime preset，不是用户要的交互 CLI；它不出现在 CLI 启动列表中 |

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 状态 DTO 只传稳定 launcher ID；本地白名单才能解析 executable / bundle；shell 参数始终单引号转义 |
| 隐私 | UI、帮助文字和错误不显示 Home 绝对路径、凭据或进程参数 |
| 紧凑 | 318px 级弹窗使用分段切换，名称/摘要可截断，尾部按钮宽度固定 |
| 可扩展 | 新 CLI 由 Host launch descriptor + Client 白名单双向确认；新 Desktop 通过新增受管 spec 接入 |
| 可测试 | 目录解析、缺失态、运行态、命令引用和 launch descriptor 约束使用合成数据测试 |

## 6. 已证伪选项

- 直接执行 `AgentHarnessItem.cliCommand`：已证伪。`cxspark` 状态中的基础命令是 `codex`，这会打开错误 route，同时使 API 变成任意命令输入面。
- 把 Desktop 塞进 `AgentHarnessItem`：已证伪。Desktop 安装/运行态与 harness 可用性是两个领域。
- 同时铺开两个长列表：不适合当前窄弹窗，采用 CLI/Desktop 分段切换。
