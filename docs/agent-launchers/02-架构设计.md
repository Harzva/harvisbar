# HarvisBar Agent 启动目录：架构设计

前置文档：`01-需求分析.md`

## 1. 分层图

```text
数据 / 配置层
  Rust HarnessSpec launch descriptor
  Swift Desktop allowlist specs
            │
            ▼
服务层
  AgentLauncherCatalog
  AgentLauncherCommandBuilder
  HarvisRuntimeModel launch actions
            │
            ▼
通道层
  /bar/status (read-only launcher IDs)
  osascript -> Terminal
  NSWorkspace -> macOS application
            │
            ▼
界面层
  Agent Launchers compact panel
  CLI/Desktop segmented picker
  one button per target
```

依赖单向：Rust 状态不依赖 Swift；Catalog 不依赖 View；View 只通过 RuntimeModel 发出动作。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| `crates/harvis-integrations/src/agent_harnesses.rs` | 为真正可交互打开的 CLI harness 输出受限 launch descriptor；不输出命令参数/路径 |
| `Models/RuntimeModels.swift` | 解码 Host 的 launch descriptor，保持对旧 Host 缺少字段的兼容 |

| `Runtime/HarvisRuntimeModel+AgentLaunchers.swift` | 处理白名单复核、防重复、Terminal / NSWorkspace 打开和安全错误反馈 |
| `Runtime/HarvisRuntimeModel.swift` | 保存逐目标 opening ID 集合 |
| `MenuBar/HarvisPopoverView.swift` | 保存 CLI/Desktop 分段选择状态 |
| `MenuBar/HarvisAgentPopoverSection.swift` | 渲染目录、摘要、可用性和逐项按钮 |
| `Tests/HarvisBarTests/AgentLauncherTests.swift` | 测试目录总数、缺失/运行态、白名单、shell quoting 和兼容解码 |

## 4. 契约

### 4.1 Host launch descriptor

```json
{
  "launcherID": "harvis.cli.codex",
  "productID": "codex",
  "kind": "cli",
  "mode": "new-terminal-session",
  "workingDirectoryPolicy": "workspace-root"
}
```

约束：

- `launcherID` 是稳定、非敏感、无参数的行为 ID。
- descriptor 不包含 executable path、shell 文本、参数、凭据或本机绝对路径。
- Swift 客户端必须再用编译时白名单确认 `launcherID`；Host 单方输出新 ID 不会自动获得执行权。
- runtime preset 默认不具有该 descriptor，除非它后续实现了专门、可审批的交互启动器。

### 4.2 Client launch target

```text
AgentLaunchTarget
  id / productID / launcherID
  kind: cli | desktop
  label / subtitle
  availability: available | running | missing | misconfigured | unsupported | unknown
  availabilityReason
  launchMode: newTerminalSession | activateOrOpen
  statusCode / detailSummary
  resolvedResourceURL?   # 只存在当前进程内，不显示、不持久化
```

## 5. 数据流

### CLI

```text
HarnessSpec
  -> /bar/status agentHarnesses.items[].launch
  -> Swift 解码
  -> launcherID 白名单解析 executable
  -> AgentLaunchTarget
  -> 用户点击
  -> 再解析 + opening guard
  -> 安全引用 workspace/executable
  -> Terminal do script
  -> dispatched / failed
```

### Desktop

```text
Desktop allowlist spec
  -> NSWorkspace bundle lookup + standard app-name fallback
  -> running application lookup
  -> AgentLaunchTarget
  -> 用户点击
  -> 再解析 + opening guard
  -> NSWorkspace.openApplication
  -> activated-or-opened / failed
```

## 6. 状态机

```text
missing / unsupported / misconfigured
  -> 按钮保留但禁用

available / running
  -> opening
  -> dispatched (CLI) / activated-or-opened (Desktop)
  -> available / running

opening
  -> failed
  -> 恢复原可用状态，记录安全错误
```

CLI 的 harness health 与 launch availability 分开：health 作为行状态摘要，是否能打开取决于白名单和本地 executable 发现。

## 7. 扩展点

- 新 CLI：Host 声明 descriptor，Swift 显式增加同 ID 白名单，两侧契约测试通过后才可打开。
- 新 Desktop：新增 bundle ID + 标准 app name spec，无需改 Host route。
- 新打开模式：只能通过新 enum case 与显式 action implementation 加入，不接受动态 shell template。
- 未来可将 Desktop spec 上移 Host catalog，但 Client 白名单复核仍保留。

## 8. ADR 简表

| ADR | 取舍 | 原因 |
| --- | --- | --- |
| ADR-01 | CLI/Desktop 是启动目录，不是统一 harness 类型 | Desktop 安装/运行与 route health 不同 |
| ADR-02 | Host 只发 launcher ID，Client 白名单复核 | 防止本地状态 API 变成任意命令执行面 |
| ADR-03 | Desktop 使用 `activate-or-open` | 通用目录没有账号隔离上下文，不应默认 `open -n` |
| ADR-04 | CLI/Desktop 使用分段切换 | 保持弹窗密度并让尾部按钮保持可点 |
| ADR-05 | runtime preset 默认不暴露为 CLI | 避免绕过 prompt、审批和专用 wrapper 语义 |
