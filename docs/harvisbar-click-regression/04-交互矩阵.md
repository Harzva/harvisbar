## 磁盘动作

每个有效本地可浏览卷包含：

1. Show：Finder 选择该卷根路径。
2. Copy：剪贴板精确等于 `volumeURL.path`。
3. Open：Finder 打开同一 `volumeURL`。

按钮 ID 使用 `internal|external` + 固定 FNV-1a token，不嵌入绝对路径；Help 和反馈仍向用户显示真实根路径。网络卷、不可浏览卷、只读外接卷与分类未知卷在容量探测前跳过。

隔离进程上的真实 OS 闭环结果：

- Copy：系统根卷与两块外接卷 3/3 精确匹配其运行时 `volumeURL.path`，反馈匹配，原剪贴板完整恢复。
- Show/Open：上述 3 个卷共 6/6 AXPress、Finder 目标或选中项、反馈均匹配。
- Finder 使用专属哨兵窗口，保护原窗口 `807`；测试后窗口 ID 集、原窗口属性、选中项、原 HarvisBar 页面与滚动均恢复，警告 0。

5 个原本只有“按下成功”但无可观察终态的刷新入口已增加稳定 ID 和完成计数：Remote、Codex alignment、Agent catop、DSH catalog、agy proxy。最终实际 AX 点击为 5/5，通过 `Ready → Completed 1` 或 `Completed n → Completed n+1` 证明本次刷新完成。

## 正式菜单卡死回归

首个 `0.35.0` 候选包在真实菜单栏状态项点击时暴露出确定性卡死：主线程在 SwiftUI 构建头像期间同步执行文件 `open/read`，而旧偏好把插件根指向外置开发卷。AXPress 只是让同步阻塞更容易被观测；普通鼠标打开同一 Popover 也会进入相同路径。

修复后的契约为：

- 正式包的 receipt/provenance 资源根始终优先于旧开发根，并回写已迁移的偏好。
- 头像资源根在模型启动时固定，不跟随配置文本框逐字符变化。
- 两个头像消费者共享模型级 single-flight；同一模型在成功、失败、取消等待者和重复开关后都只发起一次读取。
- 文件读取在 utility detached task 中完成，并在返回 MainActor 前复制为 heap-backed Data；View 内禁止 `fileExists`、`Data(contentsOf:)` 和 `NSImage(contentsOfFile:)`。
- 外置卷容量枚举同样移出 MainActor；一个扫描未完成时不启动第二个扫描，菜单仍可响应。

自动回归覆盖 20 个并发消费者、取消后重开、失败负缓存、非主线程读取、可编辑插件根隔离，以及阻塞磁盘扫描下 MainActor 心跳和 20 次刷新不重复发起。候选包必须再通过真实状态项点击的有界 live probe，才允许替换正式安装。

## 测试夹具事故与恢复边界

早期浏览器夹具把 Chrome 大窗口 ID 解析成科学计数法，误关闭了原有 4 个单标签窗口。已通过 Chrome 的“重新打开关闭的窗口”恢复为 4 个窗口、每窗 1 个标签，且本轮 localhost 测试标签为 0；由于事故前没有记录原 URL、标题和顺序，内容级完全一致无法证明。该夹具已永久停用，后续 URL 验收全部使用无浏览器副作用的契约测试。Finder 测试没有复用该清理逻辑。
