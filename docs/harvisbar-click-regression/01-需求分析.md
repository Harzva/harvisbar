# HarvisBar 闭环点击回归：需求分析

## 目标

对“实际安装并正在运行的 HarvisBar”建立可重复的闭环验收，避免只验证编译、签名、进程存活或局部截图，却遗漏按钮、路由、版本、权限与安装细节的问题。

## 必须做

1. 核对源码、Release 产物、打包舞台、receipt、正式 `.app` 与运行进程是同一版本和同一份功能集。
2. 覆盖菜单栏入口、12 个导航页、全局底部操作、弹窗/表单/菜单、从 HarvisBar 打开的桌面窗口或本地页面。
3. 每个可交互元素都记录：前置条件、点击动作、可观测结果、恢复动作、实测证据。
4. 正向路径与失败/禁用路径都要验证；不得把“按钮存在”当成“功能成功”。
5. 剪贴板、Finder/浏览器/Terminal 窗口、主题、选中页、配置、临时文件与进程必须在测试后恢复或清理。
6. 对可能修改用户数据、保存凭据、执行任务/模型调用、安装系统扩展等高风险操作，必须使用隔离夹具/临时数据，或只验证安全拦截路径。

## 关键验收场景

### A. 版本与包一致性

- 源码 workspace 版本、打包默认版本、Info.plist、系统扩展、receipt 和 provenance 必须一致。
- 新安装版本不得无说明地低于已安装/备份版本。
- 正式进程必须从正式 Applications 路径运行，且只有一个实例。
- 打包不得丢失 Desktop/Documents/Downloads/Network/Removable Volumes 等必需用途描述。

### B. 导航与可达性

- 12 个导航按钮均可点击，页面标题/关键控件随之变化，关闭重开后不得陷入不可导航的滚动位置。
- 所有图标按钮有唯一、可读的 AX label/help，不允许 `<unlabeled>` 交互元素。
- 动态页面在加载、空数据、部分可用、错误和过期状态下都不得显示伪造或旧数据。

### C. 动作闭环

- 磁盘：复制结果必须是该卷根路径；Finder 必须打开同一路径；无效/残留卷不得反复报错或生成可点击假项。
- 本地页：必须打开 `127.0.0.1` 上正确 path/query，页面返回成功且不泄露 token。
- 窗口/应用：要验证目标 bundle/process/window，不得只验证 API 调用返回。
- 复制：要验证剪贴板类型和精确值，并恢复原剪贴板。
- 刷新/重启：要验证加载态、终态、进程/服务状态和错误可见性。

## 非功能要求

- 回归必须可重复执行，并输出机器可读结果与人类可读报告。
- 测试期间不输出 token、凭据值、原始记忆或私有聊天内容。
- 任一点击失败要能定位到页面、元素、前置条件和实际结果。
- 安装后至少连续观测一个完整刷新周期，无崩溃、重复实例或循环错误。

## 已知风险

- 上一次正式包显示 `0.33.0`，而旧备份显示 `0.34.0`。
- 上一次本地 ad-hoc 包为保证可启动，移除了需要 Apple 证书的 Network/System Extension entitlements。
- 当前打包脚本生成的 Info.plist 缺少旧包已有的用户文件夹和卷用途描述。
- SwiftUI MenuBarExtra 的屏外 AX 元素暴露不稳定，不适合作为唯一点击驱动方式。
- 真实账户、凭据、系统扩展和任务执行不能在无隔离情况下穷举点击。
