# HarvisBar 权限与稳定 helper 恢复：验收报告

结论：通过。旧运行态的失效 cache executable 已被当前 App 内置 runtime 取代；HTTP 与 tick LaunchAgent 均固定到 profile 下的稳定 helper。外置工作区访问恢复，`task-progress` 读取失败不会再把整个 HarvisBar 变成全局红色错误。

## 构建与来源

- 本地修复提交：`8a35621bfd1f8eb1eda3e3ba69a84ea5c365a048`。
- App 版本：`0.35.1`；API：`v0.40-rust-alpha`。
- Rust workspace：266 tests passed；Swift：430 tests passed。
- Rust/Swift Release 构建通过；编译产物的源码、用户目录、外置卷及临时 target 绝对路径扫描通过。
- provenance v2、bundle receipt、runtime SHA 与深度 codesign 校验通过。
- 当前构建为 ad-hoc 签名；本报告只确认稳定路径与 receipt/SHA identity，不宣称跨版本稳定的 TCC signer identity。

## 安装与 LaunchAgent

- 替换前已备份旧 App 及 HTTP/tick 两份 plist；旧 HTTP executable 本来已经缺失，因此备份用于审计和结构恢复，运行故障应优先 forward recovery。
- stable helper 是可执行普通文件且非 symlink；其 SHA 与 App 内置 runtime、receipt 三方一致。
- HTTP 与 tick plist 均通过 lint，`ProgramArguments[0]` 精确指向 stable helper，且不再包含 plugin cache 或开发 target 路径。
- 两个 label 均已加载并处于 running；HTTP 实际 PID executable 来自 stable helper。
