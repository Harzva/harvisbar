# HarvisBar 权限与稳定 helper 恢复：架构设计

## 基线与来源

- Git common repo：本机 canonical Harvis repo（路径只作运行时证据，不写入公开文档）。
- 热修基线：已安装 0.35.0 的 ad-hoc build commit `b4b06a7`；新产物版本为 0.35.1。
- 隔离 worktree：独立的本地 hotfix worktree（不记录机器绝对路径）。
- 断链 worktree 只作为恢复 `task-progress` 行为的只读参考，不作为构建或提交来源。

## 失败边界

```text
task-progress optional-store read
  ├─ 成功 → 正常 taskProgress DTO
  └─ 无法打开、条目损坏/不安全、超时或超过预算
       ├─ GET /task-progress → 200 + status=skipped + warning
       └─ /bar/status → 200 + taskProgress.status=skipped + warning
```

降级 DTO 不包本地绝对路径、OS 原始文案或私密数据；固定使用空 `items`、`current=null`。写入等非可选路径沿 `anyhow` error chain 识别 `io::ErrorKind::PermissionDenied`，映射为 403/`permission_denied`；其他 I/O 映射为 500，worker join failure 也不再伪装成 400。

`GET /task-progress` 是 public-safe 投影，固定 `includesLocalAbsolutePaths=false`；`include_local=true` 明确拒绝，不透传持久化记录中的 `local` 或原始 `source` 对象。独立 GET 具有 5 秒响应超时、协作取消、512 个目录条目与单记录 256 KiB 上限；超限不返回部分结果。

`POST /task-progress` 只在记录明确不存在时新建；既有记录的 metadata、读取、JSON、对象形状或大小校验失败均 fail closed。状态目录与记录拒绝符号链接，写入使用同目录 `create_new` 临时文件、同步后原子替换，防止跟随链接覆盖 workspace 外目标。

## LaunchAgent 与 helper

1. 构建且校验同一 hotfix revision 的 Rust runtime 和 HarvisBar bundle receipt。
2. 使用 Rust `service-manager` 安装器校验 receipt/runtime SHA，原子复制到 `~/.harvis/bin/harvis`。
3. LaunchAgent `ProgramArguments[0]` 固定为上述稳定路径，不再引用 plugin cache 或外置卷 `target/` 产物。
4. 迁移前备份 plist 并记录 PID/executable/SHA；失败时恢复旧 plist 和旧 App，不删除用户数据。

## 签名决策

本机 `security find-identity -p codesigning` 结果为 0，所以本阶段能保证的是“稳定安装路径 + receipt/SHA 身份”，不宣称 ad-hoc 签名具有跨版本稳定 TCC 身份。如果迁移后 macOS 仍拒绝外置卷，需由用户确认后给定安装实体授权；后续要获得跨版本稳定代码身份，必须配置可持续代码签名证书。

## 验收分层

- 单元：PermissionDenied 分类、可选存储的打开/读取/损坏降级 DTO，以及写路径和其他组件错误继续 fail closed。
- API：三个 endpoint 的 HTTP status、envelope、脱敏与字段契约。
- 服务：plist 路径、PID、可执行文件存在性、SHA 一致、无旧 cache 路径。
- UI：真实安装 App 刷新、无全局 Attention，关键状态与 API 一致。
