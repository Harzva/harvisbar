# HarvisBar 权限与稳定 helper 恢复：需求分析

## 目标

在不带入 canonical/cache 现有脏改动、不使用断链旧 worktree 的前提下，以 0.35.1 本地热修恢复 HarvisBar 的 HTTP 服务和真实界面。

## 成功标准

1. `local.harzva.harvis.http` 不再运行已删除的 plugin-cache 产物，而是固定到可校验的稳定 helper 路径。
2. 外置卷 workspace 可被 helper 读取；若 `task-progress` 受限，只降级该可选组件，`/bar/status?full=true` 仍返回 200 和其他数据。
3. 独立 `GET /task-progress` 对可选存储读取失败返回 200/`status=skipped` 和脱敏 warning；`POST /task-progress` 的写入权限失败则返回稳定 `permission_denied`/403，不再误标为 `invalid_request`/400。
4. `/health`、`/bar/status?full=true`、`/task-progress` 在实际 LaunchAgent 上通过闭环复测。
5. 真实 HarvisBar 无全局红色 `Attention` 错误，刷新和基本导航可用。

## 边界

- 本次只做本地热修、安装、LaunchAgent 迁移和闭环验收；不 push、不 tag、不发布远程仓库。
- 不删除断链旧 worktree，不覆盖 canonical 根目录或 plugin cache 的用户改动。
- 不伪造或自动扩大 macOS 隐私权限；若必须在系统设置中授权，在点击前请用户确认。
- 不在本阶段修改 DSH Codex Index；HarvisBar 闭环通过后再进入 Stage 2。

## 风险

- 本机无可用的持久代码签名身份；ad-hoc 签名的 designated requirement 绑定 CDHash，不能保证跨版本 TCC 授权继承。
- 0.35.0 可追溯源码不含断链 worktree 中的 Rust `task-progress` 实现，必须以最小、可测补丁移植。
- 外置卷权限可能同时受 TCC 和进程身份影响，要分开验证“路径稳定”与“已授权”。
