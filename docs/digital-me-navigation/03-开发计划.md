状态：已完成；Phase 0–4 均已完成，保留两项非阻断现场复核  
原则：先建立稳定基线，再按数据投影、导航 UI、验收顺序推进。

## 1. 执行前置

当前 HarvisBar 工作树仍有其他 Agent Launcher 恢复工作持续写入，且导航源和测试也处于未稳定状态。实施前必须：

1. 等并行写入结束，确认相关文件归属。
2. 记录当前 `git status`，不覆盖、不清理用户或其他任务的改动。
3. 取得一次可复现的 HarvisBar 全量测试与 Release 构建基线。
4. 若基线因无关改动失败，先由对应任务完成或明确隔离；本功能不顺手修复无关代码。
5. 禁止使用 `git add -A`，只暂存本功能明确创建或修改的文件。

## 3. 风险与控制

| 风险 | 等级 | 控制措施 |
| --- | --- | --- |
| 与并行 Agent Launcher 修改冲突 | 高 | 等待稳定基线；不并行编辑同一导航文件 |
| 新 case 定义了但未渲染 | 高 | `navigationRows` 扁平化必须完整等于 `allCases` |
| 裸数字抢占输入 | 高 | V1 不注册数字快捷键；手验输入框 |
| Review 在小窗口误操作 | 高 | 弹窗只读，决策深链接到完整 Review Center |
| Work 与 Overview/Codex 重复 | 中 | Work 只做跨运行时工作聚合，域控制留在原页面 |
| Memory 与 Knowledge 混淆 | 中 | 文案明确 Memory Vault/snapshot 与 external knowledge 的边界，不显示不可信 accepted 计数 |
| 第三排压缩首屏 | 中 | 保持短标题，真实 318×620 验收，必要时分离 picker 与内容滚动 |
| 数据来源暂时不完整 | 中 | `nil` 表示不可用，禁止伪造 `0` |
| Persona Editor 与 Builder 入口混淆 | 低 | 主动作 Editor，次动作 Builder，标题清晰区分 |
